KaHyPar Project Study · Day 07

两条路线深入比较：
一次 k-way，还是多次 2-way

direct 与 recursive 共享 Hypergraph、多层算法、工厂和指标，却拥有不同的全局状态。前者始终维护一个 k-way 分区；后者维护子图栈、块编号区间和逐次变化的二分平衡目标。

分流 partition::partitionDirect one hypergraphRB stack + mappings
01 · Goals

今天不是比较“谁更好”，而是比较状态语义

Direct k-way一次多层生命周期同时产生 k 个块，局部搜索直接操作最终 block IDs。
Recursive bisection把最终块区间不断二分，每个子问题仍只看 part 0 与 part 1。
先记结论 两条路线都会执行 coarsening → initial partitioning → uncoarsening/refinement；区别不在有没有多层，而在多层闭环被调用几次、每次 Context 表示什么。
02 · Fork

统一预处理后，只在一个 switch 分流

switch (context.partition.mode) {
  case recursive_bisection:
    recursive_bisection::partition(hypergraph, context);
    break;
  case direct_kway:
    direct_kway::partition(hypergraph, context);
    break;
}

分流前的 Partitioner 已完成 Context 派生、deduplication、sanitize、large-edge 处理、可选 sparsifier 与 community detection；分流后再统一 postprocess 和恢复冗余。

因此配置不能机械横比 direct 与 recursive 预设中的 c-type、weight penalty、refiner 等，是各自经过实验调优的一整套组合，不是只改 mode 的同一算法。
03 · Direct k-way

一张图、一个最终 k、一个全局 part ID 空间

创建一次 coarsener 和 refiner
模板类型由顶层 c-* 与 r-* 参数决定。
执行一次 multilevel::partition
最粗层初始划分直接产生 0..k-1 的 block IDs。
逐层 k-way refinement
节点可以从当前块移动到任意相邻块，直接优化 cut 或 km1。
可选 V-cycles
保留已有 partition，只在同块内收缩，再展开寻找更好解。

所有节点始终属于同一个 Hypergraph 对象。part weights、pin counts、connectivity sets 和 gain cache 都围绕最终 k 个块维护。

每次只做 2-way，但目标区间越来越小

以 k=6 为例，第一次二分不是追求 50/50 的节点数，而是让两边分别承载 3 个最终块的容量。随后从 part 1 和 part 0 提取子超图，继续处理各自的 block-ID 区间。

createCurrentBisectionContext 把 partition.k 临时设为 2，并根据 k0/current_k 与 k1/current_k 计算两边的 perfect/max part weights。

05 · Stack Machine

递归逻辑用显式栈和三态状态机实现

状态动作下一步
unpartitioned为当前 [lower_k,upper_k] 建 2-way Context，跑一次 multilevel提取 part 1，压入右子问题
partitionedAndPart1Extracted右子问题返回后，从保存的父图提取 part 0压入左子问题，父状态改 finished
finished两个子区间都完成，检查 late restart弹栈，或提高 balancing level 重做

MappingStack 保存每次子图 ID 到父图 ID 的映射。到达叶子 lower_k == upper_k 时，originalHypernode() 逆向穿过映射栈，把该子图所有节点写入最终 block ID。

为何不用语言递归 显式状态让 late restart 可以回到一个父子图、重置其状态并重跑，也让子图所有权和 mapping 生命周期更清晰。

07 · Objective

Recursive 怎样用 2-way cut 服务最终 km1

一次二分只看两个 part，cut 与 km1 在该层数值相同；但最终 km1 需要累计一条超边跨越多个叶块的次数。提取子图时，extractPartAsUnpartitionedHypergraphForBisection 使用 cut-net splitting：

若超边完全在另一个 part，当前子图忽略它。
若当前 part 中 pin 数不超过 1，提取后会成为 single-node edge，也忽略。
否则在当前子图保留同权重超边，只复制属于该 part 的 pins。

这样一条超边每在递归树的一层被分开一次，就贡献一次 edge weight，累计结果对应 connectivity-1。由于 2-way FM 在循环里维护 cut，最终还会显式重算原图 km1。

1. k=5 的第一次分裂

km=2，左区间承载 2 个最终块，右区间承载 3 个最终块。源码先压入 part 1 对应的 [k1+km,k2]。

2. 嵌套路线

顶层 direct 只调用一次 k-way 多层闭环；到最粗层时，initial::partition 可以把这个局部任务交给 recursive 路线。返回后仍是一个 k-way 初始解，继续由顶层 direct 展开。

3. MappingStack

每次提取子图都会重编号。叶子 ID 只在当前子图内有效，必须逆序应用所有 mapping 才能得到输入 Hypergraph 的节点 ID。

4. km1

贡献 (4-1)×weight = 3×weight。cut-net splitting 会让它沿递归结构累计三次分裂贡献。

5. 语义示例

需要直接围绕最终 k 个块做 k-way move 时，direct 的状态更自然；需要把最终块理解成层次化二分结果，或使用两块专用 refinement 时，recursive 的状态更自然。
