03 · Rating

Heavy-edge rating 怎样累计

对节点 u 的每条 incident hyperedge e，给边内其他节点 v 累加一份分数。默认 heavy-edge 策略是：

score(e) = weight(e) / (size(e) - 1)
rating(u,v) = Σ score(e) / penalty(weight(u), weight(v))

小而重的超边贡献更高，因为它更像明确的局部关联。若启用 MultiplicativePenalty，分母是 weight(u) × weight(v)，会降低两个重节点继续合并的倾向；NoWeightPenalty 则固定除以 1。

边界细节 只遍历 edgeSize(e) <= hyperedge_size_threshold 的边。超大边连接面太广，拿它判断局部亲密度通常信息不足。
04 · Policies

一个候选要通过六层门

层源码条件拒绝的情况
1. 邻接共同出现在某条 incident edge没有共享超边
2. 重量w(u)+w(v) <= max_allowed_node_weight粗节点会过重
3. 分区RatingPartitionPolicy::acceptV-cycle 中跨已有块收缩
4. 社区sameCommunity(...)社区感知模式下跨社区
5. 接受策略更高 rating 或平局策略不是当前最佳，或平局未胜出
6. 固定点FixedVertexPolicy::acceptContraction破坏 fixed-vertex 约束

BestRatingPreferringUnmatched 在同分时偏好还没被匹配过的节点，使一个 pass 中的收缩更均匀；tie-breaking policy 再决定完全相等时取 first、last 还是 random。

05 · Worked Example

用单元测试手算 rate(3)

测试图包含 e1={0,1,3,4} 和 e2={3,4,6}，边权均为 1，节点权均为 1。节点 3 与节点 4 同时共享两条边。

e1 的贡献
1 / (4 - 1) = 1/3
e2 的贡献
1 / (3 - 1) = 1/2
累计并除 penalty
(1/3 + 1/2) / (1×1) = 5/6
测试断言
rate(3).value == 5.0/6，target == 4

06 · Main Loop

MLCoarsener 的一个 pass

while (currentNumNodes > contraction_limit) {
  shuffle(nodes)
  rater.resetMatches()
  for (hn : nodes) {
    rating = rater.rate(hn)
    if (rating.valid && both nodes enabled) {
      performContraction(rating.target, hn)
      rater.markAsMatched(rating.target)
    }
  }
}

performContraction 把 Day 02 的底层动作封装成生命周期步骤：Hypergraph::contract 返回 memento，压入 _history；随后 pruner 删除单点边、合并平行边，并记录恢复信息。

不要漏掉 pruner contraction 只负责节点与 pin 状态；粗化器必须额外处理收缩后产生的 size-1 hyperedge 和 parallel hyperedge，否则指标与后续遍历都会含有冗余结构。
07 · Implementations

ML、full、lazy 的差别在“多久重算”

实现选择方式理解重点
MLCoarsener打乱节点，每个 pass 为当前节点即时评分简单、局部、匹配式
FullVertexPairCoarsener为节点维护全局 priority queue，并主动更新受影响评分信息新鲜，更新成本较高
LazyVertexPairCoarsener先标记 rating 过期，弹到队首时再重算避免大量无用更新

预设 km1_kKaHyPar_sea20.ini 使用 c-type=ml_style；recursive 预设常用 heavy_lazy。不要从算法名猜行为，直接沿 registrar 找到具体类型。

09 · Practice

练习与答案核对

  • 一条权重为 6、包含 4 个 pin 的超边，对其中一对节点贡献多少 heavy-edge score？
  • 为什么社区检查在“累计候选分数”之后做也仍然正确？
  • 解释 V-cycle 中为什么不能跨当前 partition 收缩。
  • 把 no_penalty 改成 multiplicative，说明重节点对的排序怎样变化。
  • 运行三个 coarsening 测试，并找出“平行边逆序恢复”的测试名。
1. 分数

6 / (4-1) = 2。如果两节点还共享其他超边，要继续累加。

2. 社区过滤为何可后置

SparseMap 先收集所有相邻候选；最终寻找最大值时只接受同社区候选。后置不会让跨社区节点获胜，只是让评分循环保持紧凑。

3. V-cycle 的分区约束

V-cycle 已有一个待改进分区。若跨块 contract，会把属于不同块的节点绑定成同一个粗节点，破坏该分区在粗层上的可表示性。

测试结果

本地验证：vertex-pair rater 7 项、full coarsener 14 项、lazy coarsener 13 项全部通过。对应测试名是 AnUncoarseningOperation.RestoresParallelHyperedgesInReverseOrder。
