03 · Mental model

KaHyPar 究竟在优化什么

从图到超图

普通图的一条边连接两个顶点；超图的一条 hyperedge 可以连接任意多个顶点。顶点属于某条超边的关系称为一个 pin。

k-way 划分与平衡

目标是把顶点集合分成 k 个互不相交的块，同时限制每个块的总权重。若顶点权重为 c(v)，典型上界为：

c(Vi) ≤ Lmax = (1 + ε) · ⌈ c(V) / k ⌉ε 控制允许的不平衡程度

如果只追求切割质量，把所有节点放进同一块就能得到 cut = 0，但它显然违反负载平衡。因此目标函数与平衡约束必须一起看。

cut 与 km1

令 λ(e) 表示超边 e 跨越的块数。cut 只关心“有没有被切”；km1 还关心“跨了多少块”。

cut(Π) = Σe : λ(e)>1 ω(e)     |     km1(Π) = Σe (λ(e) − 1)ω(e)
第一个易混点km1 是目标函数；direct 与 recursive 是顶层划分路线。CLI 中分别由 -o 和 -m 指定。

05 · Execution path

第一次完整追踪

入口只做四件事

从 kahypar/application/kahypar.cc:37 开始：

kahypar/application/kahypar.cc
int main(int argc, char* argv[]) {
  kahypar::Context context;
  kahypar::processCommandLineInput(context, argc, argv);

  kahypar::Hypergraph hypergraph(
    kahypar::io::createHypergraphFromFile(
      context.partition.graph_filename,
      context.partition.k,
      VALIDATE_INPUT, PROMOTE_WARNINGS_TO_ERRORS));

  kahypar::PartitionerFacade().partition(hypergraph, context);
  return 0;
}
  1. 创建 Context，承载配置与运行状态。
  2. 合并命令行参数和 INI 预设。
  3. 从 .hgr 文件构造 Hypergraph。
  4. 把图和上下文交给 PartitionerFacade。

Facade 与 Partitioner 的边界

PartitionerFacade 管“一次任务怎样运行”：随机种子、固定点、已有划分、限时重复、进化模式和最终输出。Partitioner 管“核心算法怎样走完生命周期”：统一预处理、路线分流和结构恢复。

06 · Two routes

相同目标，不同分解方式

顶层分流发生在 kahypar/partition/partitioner.h:75：

顶层路线分流
switch (context.partition.mode) {
  case Mode::recursive_bisection:
    recursive_bisection::partition(hypergraph, context);
    break;
  case Mode::direct_kway:
    direct_kway::partition(hypergraph, context);
    break;
  case Mode::UNDEFINED:
    std::exit(-1);
}
-m direct

Direct k-way

一次顶层多层划分直接构造 k 个块。

  • 全局同时看到多个块的选择
  • 入口：direct_kway.h
  • 先运行 multilevel，再按需做 V-cycle
  • README 的一般推荐路线
-m recursive

Recursive bisection

把 k-way 问题递归拆成多个 2-way 子问题。

  • 维护子超图、块区间与映射栈
  • 入口：recursive_bisection.h
  • 每次二分重新处理平衡容忍度
  • 状态更多，适合在主线之后阅读
第二个易混点mode=direct 与 i-mode=recursive 可以同时出现。前者是整次任务的顶层路线；后者只是最粗超图产生初始解的内部策略。
07 · Shared core

两条路线共享的多层骨架

KaHyPar 的核心不是一次把节点扔进不同桶，而是先缩小问题，再在恢复过程中持续改进。

1. Coarsening反复收缩相似节点，构造越来越小的超图。
→
2. Initial partition在最粗超图上构造满足平衡约束的初始解。
→
3. Uncoarsen + refine逐层撤销收缩，并在每一层做局部搜索。

KaHyPar 使用很细粒度的 n-level 思路，层与层之间通常只收缩一个顶点。层数更多，但局部搜索获得了更细致的改进机会。

工厂模式在这里的作用主流程不硬编码 coarsener 或 refiner。INI 写入 Context，工厂据此创建具体实现；主流程保持稳定，算法组合可以替换。
08 · Input

读懂今天的 .hgr 实例

KaHyPar 使用 hMetis 格式。无权超图首行是 <num_hyperedges> <num_hypernodes>，随后每行描述一条超边。文件节点编号从 1 开始，读取后会转成内部 0-based ID。

tests/io/test_instances/unweighted_hypergraph.hgr
% hypergraph without hyperedge and hypernode weights
4 7
1 2
1 7 5 6
5 6 4
2 3 4

它表示 7 个节点、4 条超边：

E = { {1,2}, {1,7,5,6}, {5,6,4}, {2,3,4} }
记住头部顺序是“超边数、节点数”，与很多人第一眼猜测的顺序相反。

闭卷自测

1. 为什么必须同时关注目标函数和平衡约束？

只最小化 cut 会偏好把所有节点放进一个块；平衡约束保证计算或存储负载可用。

2. k=2 时，cut 与 km1 为什么相等？

被切超边只能跨两个块，因此每条被切超边对 cut 贡献 ω(e)，对 km1 贡献 (2−1)ω(e)。

3. Facade 与 Partitioner 的职责差别是什么？

Facade 负责任务外围编排；Partitioner 负责预处理、核心算法调用与结构恢复。

4. mode=direct 与 i-mode=recursive 为什么能同时出现？

前者决定顶层任务路线，后者只决定最粗层内部如何产生初始解，处于不同配置层级。

5. multilevel 的三个阶段是什么？

Coarsening、initial partitioning、uncoarsening + refinement。

一句话心智模型

KaHyPar 读取一个超图和一组分层配置，在平衡约束下选择 direct 或 recursive 路线；每个子问题再通过收缩、最粗层初始划分、逐层展开与局部改进得到高质量分区。
