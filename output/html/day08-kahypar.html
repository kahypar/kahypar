02 · Surfaces

三个入口，最后都到同一个核心

CLIcommand_line_options
C APIopaque handles
Pythonpybind11 classes
Facadetask orchestration
Partitionercore lifecycle

CLI 负责字符串参数与文件输出；C API 提供稳定 ABI 和数组接口；Python 直接绑定 C++ Hypergraph 与 Context。三者不复制算法，最终都调用 PartitionerFacade().partition(...)。

设计价值 算法修复只需落在核心层，三个入口自然共享；接口层只负责类型转换、对象生命周期和用户输入校验。
03 · C API

opaque handle 隔开 C ABI 与 C++ 类型

kahypar_context_t* context = kahypar_context_new();
kahypar_configure_context_from_file(context, "config/km1_kKaHyPar_sea20.ini");
kahypar_set_seed(context, 42);

kahypar_hyperedge_weight_t objective = 0;
kahypar_partition(num_vertices, num_hyperedges, 0.03, 2,
                  vertex_weights, edge_weights,
                  hyperedge_indices, hyperedges,
                  &objective, context, partition);

kahypar_context_free(context);

头文件只声明不完整类型 kahypar_context_s 与 kahypar_hypergraph_s。实现中用 reinterpret_cast 在 handle 和 C++ 对象之间转换，调用者不依赖 Context 或 Hypergraph 的内存布局。

拼写兼容性 当前公共 API 名为 kahypar_supress_output，源码中确实少了一个 p。公共符号一旦发布，修正拼写也可能是 ABI 变更，不能当普通重命名处理。

05 · Python

pybind11 直接包装对象与迭代器

import kahypar

indices = [0, 2, 6, 9, 12]
pins = [0, 2, 0, 1, 3, 4, 3, 4, 6, 2, 5, 6]
hg = kahypar.Hypergraph(7, 4, indices, pins, 2)

ctx = kahypar.Context()
ctx.loadINIconfiguration("config/km1_kKaHyPar_sea20.ini")
ctx.setK(2)
ctx.setEpsilon(0.03)
ctx.setSeed(42)
kahypar.partition(hg, ctx)
print(kahypar.connectivityMinusOne(hg))

module.cpp 为 nodes()、edges()、pins() 返回 Python iterator，并用 keep_alive<0,1> 保证迭代器存活时 Hypergraph 不被销毁。connectivitySet 使用 reference_internal 把返回视图生命周期绑定到父对象。

构建状态 Python 默认关闭，由 CMake 选项 KAHYPAR_PYTHON_INTERFACE=ON 启用。当前主 build 已生成 CLI 和 dylib，但没有 Python extension；这是配置选择，不是构建失败。

07 · Safe Change

练习：新增“被切超边数量”指标

这不是 cut weight。它只统计 connectivity(e)>1 的超边条数，适合作为一个低风险改造练习。

先写测试
在 metrics_test.cc 的未划分图断言 0，在已有 partition fixture 断言 2。
最小实现
在 metrics.h 遍历 enabled edges，满足条件时计数。
跑窄测试
构建并运行 metrics_test，确认原 4 项和新增项通过。
决定暴露层
若只供内部统计，到此结束；若给 Python/C 使用，再分别加 binding/API 和接口测试。
跑邻近回归
至少补跑 partitioner 与 interface；改公共头时再做下游编译 smoke test。
static inline HyperedgeID numCutHyperedges(const Hypergraph& hg) {
  HyperedgeID count = 0;
  for (const HyperedgeID& he : hg.edges()) {
    count += hg.connectivity(he) > 1;
  }
  return count;
}
为什么这是好练习 它读取已经维护好的 connectivity，不改变 Hypergraph 状态、不进入性能关键的 gain 更新，也不需要新抽象；影响面容易用一条确定性 fixture 覆盖。

毕业练习

  • 闭卷画出 CLI 到最终 partition 的完整调用链。
  • 挑一个 sea20 preset，对每组键标注它作用于哪一天的模块。
  • 用 7 节点实例手算一次 rating、一次 km1 move gain 和一次 recursive block-weight 目标。
  • 按本页流程实现 numCutHyperedges，只改 metric 与测试，确认影响面。
  • 再选择 C 或 Python 其中一层暴露该指标，并补接口测试。
课程结束后怎样继续读源码？

按兴趣选择纵向专题：预处理可读 MinHash sparsifier、Louvain 和 deduplicator；质量可深入 HyperFlowCutter；全局搜索可读 evolutionary。仍坚持四问：输入、状态、动作、消费者。

改动前的最终自检

确认行为契约、最小作用域、确定性测试、正确工作目录、公共 API/ABI 影响、配置兼容性，以及未触碰无关文件。
