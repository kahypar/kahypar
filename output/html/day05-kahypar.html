KaHyPar Project Study · Day 05

Initial Partitioning：
给最粗层一个好起点

粗化完成后，超图变小了，但节点仍未分块。KaHyPar 会构造一套专用 Context，运行一个或一组初始划分器，并按“先可行、再质量、再不平衡”保存最值得展开的候选解。

入口 initial::partition组合 PoolInitialPartitioner底线 balance feasibility
01 · Goals

今天要拆开两个容易混在一起的循环

外层多层调用最粗图可再次走 multilevel 或 recursive 路线。
算法多次运行每个 initial partitioner 可因随机顺序运行多次。
Pool 多算法竞争多个启发式各自产生候选，统一比较后留一个。
关键区分 顶层 mode=direct 不妨碍 i-mode=recursive。前者决定整个任务；后者只决定最粗层如何获得初始解。
02 · Handoff

粗化到初始划分的六步交接

coarsen达到 limit
reindex提取紧凑粗图
createContext切到 IP 模式
partition生成候选解
map back写回粗图
initialize重建 cut cache

initial::partition 先调用 ds::reindex(hg)，因为粗化后的 enabled ID 可能不连续。得到的 mapping 用来把 init_hg.partID(hn) 写回原粗图对应节点。

为什么重置 communities 粗化阶段的社区标签不直接带入初始划分；代码在构造专用 Context 前执行 init_hg.resetCommunities()，是否重新检测由 IP 配置决定。

04 · Algorithm Family

Pool 里不是同一种算法换名字

家族基本思路主要差异
random随机顺序把节点放入可容纳的块便宜，作为基线和多样性来源
bfs从起点沿超图邻接扩张块偏向保持局部连通结构
lp按邻域收益传播 block label局部聚类式构造
bin_packing按容量把节点视作待装物品优先处理平衡与重节点
greedy_*维护各块候选队列，选择最大 gain 节点FM/maxpin/maxnet gain × global/round/sequential queue

这些类型由 register_initial_partitioning_algorithms.h 注册到同一个 Factory。策略组合在编译期成为具体模板类型，Pool 在运行时通过 enum 创建它们。

for (algo in pool) {
  if (bit_is_zero || algo_is_maxpin_variant) continue;
  partitioner = Factory.createObject(algo, hg, context);
  partitioner->partition();
  quality = objective == cut ? hyperedgeCut(hg) : km1(hg);
  imbalance = metrics::imbalance(hg, context);
  compare_and_store_best_partition();
}
06 · Selection Rule

不是简单选择 objective 最小者

候选可行，当前 best 不可行
无论 objective 是否更低，先把可行解升级为 best。
quality 更好
同时要求候选可行，或者至少 imbalance 也更好。
quality 相同
选择 imbalance 更小者。
所有算法结束
resetPartitioning，再恢复保存的 best_partition。

同一套比较逻辑也存在于 InitialPartitionerBase::multipleRunsInitialPartitioning()。因此一个 Pool 候选内部还可能运行 nruns 次，先选出该算法的最好结果，再参加 Pool 竞争。

源码细节 Pool 完成一次内部竞赛后把 context.initial_partitioning.nruns 设为 1，避免 Pool 自己再被基类外层重复完整执行。
07 · Balance

recursive 初始划分还会做深层平衡检查

普通 epsilon 只检查当前二分是否超重；但递归二分后，一个当前块还要继续容纳多个最终块。BinPacker::partitionIsDeeplyBalanced 会判断其中的节点能否继续装进这些未来块容量。

机制触发位置作用
prepacking开始一次二分前先固定难以安放的重节点
early restart多层划分后仍不 deeply balanced提高 balancing restriction 后重跑当前二分
late restart子问题回收时发现最终不平衡回退父状态并用更严格 level 重做

这解释了预设中的 i-bp-early-restart=true 与 i-bp-late-restart=true：它们不是一般的随机重启，而是针对“当前看似平衡、后续却无解”的结构性修复。

09 · Practice

练习与答案核对

  • 解释为什么粗图需要 reindex，而不是直接交给 initial partitioner。
  • 候选 A：quality=8、imbalance=0.05；B：quality=9、imbalance=0.02；epsilon=0.03。应选谁？
  • 为什么 i-mode=recursive 不等于整个任务走 recursive 路线？
  • 找出 Pool 中被显式跳过的三个算法变体。
  • 口述一次 multi-level initial partitioning 的嵌套调用，直到 part ID 写回原粗图。
1. reindex

粗化后 disabled 节点让有效 ID 有空洞。提取紧凑图能让算法按连续下标分配数组；mapping 保证结果能准确写回。

2. A 还是 B

选 B。A 超过 epsilon，不可行；B 可行。比较规则优先让 best 从不可行变成可行，即使 objective 稍差。

3. 两个 mode

partition.mode 控制完整任务；initial_partitioning.mode 只在最粗层构造起点。direct k-way 的内部完全可以调用 recursive bisection 生成初始解。

4. 被跳过的变体

greedy_round_maxpin、greedy_global_maxpin、greedy_sequential_maxpin。
